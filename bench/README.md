# 中文找数基准

用数据判断"一个改动值不值得"，而不是凭感觉调参。

```bash
datafinder bench pool    # 汇集各方案 Top-N 里还没标注的候选 → bench/out/pool.tsv
# …按 queries.zh.yaml 里的 intent 标注，追加到 judgments.tsv…
datafinder bench run     # 比较各方案：nDCG@10、P@5
```

- `queries.zh.yaml`：14 条中文找数问句（人口、经济、环境、气象、农业、卫生、金融、地理、房产、AI、交通），每条写明相关性口径。
- `judgments.tsv`：`qid  key  grade  labeler  title`。grade：2 直接相关 / 1 部分相关 / 0 无关。**标注者必须写明**（`agent` / `human`）。key 是数据集的 DOI 或规范化 URL。
- 对比的方案（同一批检索结果上只换排序，差异不来自网络波动）：
  - `datafinder` 完整引擎 · `无加成` · `无覆盖度` · `仅RRF`：逐项关掉看贡献
  - `dsk-原句`：把中文原句直接交给 Dataseek、用它自己的排序（"黑盒封装"基线）
  - `dsk-英文词`：把我们翻译好的英文检索词交给 Dataseek、用它自己的排序

## 选题验收与分面检索验收

排序基准之外还有两套"验收集"，用真实任务检查整条链路（目录检索 → 找数方案）：

- `topics.yaml` / `topics.holdout.yaml`：真实研究选题（开发集 12 题 / 留出集 10 题），每题写明"应该找到什么"（门户、指标、数据表）。`datafinder bench topics [--holdout]`。
- `facets.yaml` / `facets.holdout.yaml`：直接验收分面筛选语义（开发集 25 条 / 留出集 10 条），每条写明筛选条件、至少命中什么、所有结果必须满足什么、**绝不能出现什么**（出版年冒充观测期、发布机构地域冒充覆盖地域、标题推断的粒度冒充已验证、图片冒充可分析表格……）。`datafinder bench facets [--holdout]`。

- `topics.public.yaml`：**公开来源选题集**（21 题），题目取自公开的评测集、赛事和真实用户问题，不是我们量身写的，每题标明出处与改写程度（`public` 公开原题 / `adapted` 借题型改写 / `authored` 自拟补充）。`datafinder bench topics --public`。出处：
  - [CT2C-QA](https://arxiv.org/abs/2410.21414)（ACM MM 2024）：取自国家统计局网页的中文问答集，9981 条（含"2024年1—2月份采矿业利润总额""2021年全国文化及相关产业增加值"等）；
  - 全国大学生统计建模大赛 2025（第十一届）获奖论文选题（中国统计出版社，ISBN 978-7-5230-0987-1）：县域共同富裕、长江经济带能源效率、八大区域碳排放、制造业新质化、江西生育意愿、京津冀 PM2.5 等；
  - [NTCIR-15/16 Data Search](https://ntcir.datasearch.jp/)：面向政府统计数据的公开检索评测，题目来自真实用户提问（日本 e-Stat / 美国 Data.gov），这里只借"日常问句"的题型改写成中国场景；
  - 另有 5 题 `authored` 补写，用来覆盖公开题没触及的子模块（统计公报、普查、部委、省统计局），**这类题不算公开题**，脚本会分来源汇报命中率。

  其他可借鉴但未纳入的公开资源：TableEval（EMNLP 2025，含政府数据的中英文表格问答）、HiTab（ACL 2022，统计报告的层次表问答）——它们评的是"读表回答"，不是"找到哪张表"，需要自己再设计找数口径才能用。

**留出集的纪律**：写用例时没看过检索结果，调词表/排序/规则时不许参考；发现缺口修完后，要换一批新的留出题，不要拿同一批反复调。看过缺口后修补的留出分数不再是干净的估计，会在 docs 里如实标注。

## 结果（2026-11-20，约 580 条标注）

| 方案 | nDCG@10 | P@5 |
|---|---|---|
| **datafinder（完整）** | **0.746** | 0.93 |
| 无加成 | 0.569 | 0.89 |
| dsk-英文词 | 0.495 | 0.87 |
| 仅 RRF | 0.395 | 0.66 |
| 无覆盖度 | 0.341 | 0.50 |
| dsk-原句 | 0.242 | 0.27 |

对 `dsk-原句` 14 胜 0 负；对 `dsk-英文词` 11 胜 0 平 3 负。

怎么读：
- **中文原句直接丢给 Dataseek 很差**（0.242）。把中文翻译成英文再交给它好很多（0.495），说明"查询翻译"本身有价值。
- **概念覆盖度贡献最大**（去掉后 0.746→0.341）。官方、中文、地区三项加成各有正向贡献（逐项去掉都是输多赢少）；"有资源"加成基本中性。
- **中英双路检索**（中文问句同时用中文词和英文词查 Zenodo/DataCite/Dataseek）把 nDCG 从 0.683 提到 0.746，带回了《各省粮食产量》《第七次普查人口》这类中文记录。
- 覆盖度的力度（下限/指数）做过 6 组对照，差别 ≤0.03 且胜负互现，**没有证据支持调参，保持默认值**。

## 局限（务必知道）

- **只有 14 条问句，标注者是 AI Agent**，只能当方向性证据，不是统计结论；差 0.03 以内不要当真。
- **相关性口径偏向"中国优先"**（intent 里写了"中国的最佳"），所以"官方 / 中文 / 地区"加成的收益有一部分来自口径本身。
- **标注是按候选池做的**（各方案 Top-10 的并集）。池外的好结果不会被计入，未标注的按 0 分；`Top10 未标注` 一栏应该接近 0，否则先重新 `pool`。
- **结果随网络实时变化**：来源的数据会更新，几天后重跑数字会漂移，需要补标注。
- 已知落后的问句：q07 新冠（几篇只沾边的报告排进前 10）、q02 GDP（"两个来源都找到"的一致性加分把一条描述里提到 GDP 的数据集顶到了统计局指标前面——Dataseek 与 DataCite 底层是同一批 DOI，这个一致性并不独立）。
