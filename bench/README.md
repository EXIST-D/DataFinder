# 中文找数基准

用数据判断"一个改动值不值得"，而不是凭感觉调参。

```bash
datafinder bench pool    # 汇集各方案 Top-N 里还没标注的候选 → bench/out/pool.tsv
# …按 queries.zh.yaml 里的 intent 标注，追加到 judgments.tsv…
datafinder bench run     # 比较各方案：nDCG@10、P@5
```

- `queries.zh.yaml`：14 条中文找数问句（人口、经济、环境、气象、农业、卫生、金融、地理、房产、AI、交通），每条写明相关性口径。
- `judgments.tsv`：`qid  key  grade  labeler  title`。grade：2 直接相关 / 1 部分相关 / 0 无关。**标注者必须写明**（`agent` / `human`）。key 是数据集的 DOI 或规范化 URL。
- 对比的方案（同一批检索结果上只换排序，差异不来自网络波动）：
  - `datafinder` 完整引擎 · `无加成` · `无覆盖度` · `仅RRF`：逐项关掉看贡献
  - `dsk-原句`：把中文原句直接交给 Dataseek、用它自己的排序（"黑盒封装"基线）
  - `dsk-英文词`：把我们翻译好的英文检索词交给 Dataseek、用它自己的排序

## 结果（2026-11-20，约 580 条标注）

| 方案 | nDCG@10 | P@5 |
|---|---|---|
| **datafinder（完整）** | **0.746** | 0.93 |
| 无加成 | 0.569 | 0.89 |
| dsk-英文词 | 0.495 | 0.87 |
| 仅 RRF | 0.395 | 0.66 |
| 无覆盖度 | 0.341 | 0.50 |
| dsk-原句 | 0.242 | 0.27 |

对 `dsk-原句` 14 胜 0 负；对 `dsk-英文词` 11 胜 0 平 3 负。

怎么读：
- **中文原句直接丢给 Dataseek 很差**（0.242）。把中文翻译成英文再交给它好很多（0.495），说明"查询翻译"本身有价值。
- **概念覆盖度贡献最大**（去掉后 0.746→0.341）。官方、中文、地区三项加成各有正向贡献（逐项去掉都是输多赢少）；"有资源"加成基本中性。
- **中英双路检索**（中文问句同时用中文词和英文词查 Zenodo/DataCite/Dataseek）把 nDCG 从 0.683 提到 0.746，带回了《各省粮食产量》《第七次普查人口》这类中文记录。
- 覆盖度的力度（下限/指数）做过 6 组对照，差别 ≤0.03 且胜负互现，**没有证据支持调参，保持默认值**。

## 局限（务必知道）

- **只有 14 条问句，标注者是 AI Agent**，只能当方向性证据，不是统计结论；差 0.03 以内不要当真。
- **相关性口径偏向"中国优先"**（intent 里写了"中国的最佳"），所以"官方 / 中文 / 地区"加成的收益有一部分来自口径本身。
- **标注是按候选池做的**（各方案 Top-10 的并集）。池外的好结果不会被计入，未标注的按 0 分；`Top10 未标注` 一栏应该接近 0，否则先重新 `pool`。
- **结果随网络实时变化**：来源的数据会更新，几天后重跑数字会漂移，需要补标注。
- 已知落后的问句：q07 新冠（几篇只沾边的报告排进前 10）、q02 GDP（"两个来源都找到"的一致性加分把一条描述里提到 GDP 的数据集顶到了统计局指标前面——Dataseek 与 DataCite 底层是同一批 DOI，这个一致性并不独立）。
